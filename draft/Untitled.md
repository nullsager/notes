## KVFlow 精简总结

**KVFlow** 是一种面向 LLM 多智能体工作流的前缀 KV Cache 管理方案，目标是减少重复 prefill 和 CPU–GPU 缓存传输带来的延迟。

### 核心问题

多 Agent 系统中，每个 Agent 通常有很长且重复使用的固定 Prompt。GPU 显存不足时，传统 **LRU** 可能淘汰“马上要执行”的 Agent 缓存；CPU 分级缓存又通常等请求到达后才加载，导致 GPU 等待。

### 核心方法

1. **工作流感知淘汰**
   - 根据 Agent 工作流图计算每个 Agent 距离执行还有多少步。
   - 优先保留即将执行的 Agent 前缀，淘汰短期内不会使用的缓存。
   - 动态后缀复用率低，因此优先淘汰。
   - 在 Radix Tree 上按节点管理，正确处理多个 Agent 的共享前缀。

2. **提前预取**
   - 在当前 Agent 运行时，预测后续可能执行的 Agent。
   - 异步将其 KV Cache 从 CPU 搬到 GPU，使传输与计算重叠。

3. **状态感知调度**
   - 如果某请求的 KV Cache 仍在加载，就先执行其他缓存已就绪的请求，减少 GPU 空闲。

### 实验结果

基于 SGLang 实现，特定长前缀场景下：

- 相比 HiCache，最高加速约 $2.19\times$；
- 相比原生 SGLang，最高加速约 $2.91\times$；
- 更真实的 PEER 工作流中，提升约 $1.08$–$1.12\times$。

### 结论

KVFlow 的关键贡献是：**利用多 Agent 工作流中可预测的未来执行顺序，而不是仅根据历史访问记录管理 KV Cache。**

它最适合：

- Agent 固定 Prompt 很长；
- Agent 会被反复调用；
- GPU 显存紧张；
- 工作流结构较稳定；
- 多工作流并发且输出较短。

局限是依赖工作流可预测性，分支过多可能产生无效预取，并且主要优化 prefill，对长文本 decode 的帮助有限。

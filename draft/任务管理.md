# 命令行任务管理系统 v 2.0 —— 项目理解与运行指南

## 一、快速开始

### 1.1 环境要求

- **编译器**: g++ 7.0+ 或 clang++ 5.0+（需支持 C++17）
- **操作系统**: Linux / macOS / Windows（WSL）
- **构建工具**: Make 或 CMake 3.10+

### 1.2 编译项目

**方式一：使用 Make（推荐）**

```bash
cd project2
make          # 编译
./TaskManager # 运行
```

**方式二：使用 CMake**

```bash
cd project2
mkdir build && cd build
cmake ..
make
./TaskManager
```

**方式三：直接 g++ 编译**

```bash
g++ -std=c++17 -Wall -I./include -o TaskManager src/main.cpp src/Logger.cpp src/TaskManager.cpp
./TaskManager
```

### 1.3 清理构建产物

```bash
make clean   # 删除可执行文件、数据文件、日志文件
```

## 四、核心代码逻辑详解

### 4.1 设计模式一：单例模式（Logger）

**文件**: `include/Logger.h` + `src/Logger.cpp`

**什么是单例模式？**
确保一个类在整个程序中只有一个实例，并提供全局访问点。

**实现要点：**

```cpp
class Logger {
public:
    static Logger& getInstance() {
        static Logger instance;  // C++11 保证线程安全的局部静态变量
        return instance;
    }
    Logger(const Logger&) = delete;             // 禁止拷贝
    Logger& operator=(const Logger&) = delete;  // 禁止赋值
private:
    Logger();  // 私有构造函数，外部无法 new
};
```

**关键理解：**
1. 构造函数是 `private`，外部代码无法直接创建 Logger 对象
2. `getInstance()` 使用**局部静态变量**，C++11 标准保证其初始化是线程安全的
3. `delete` 拷贝构造和赋值运算符，防止通过拷贝产生第二个实例
4. 使用 `std::mutex` 保护 `log()` 方法，实现线程安全的日志写入
5. 增加了**日志级别**（INFO/WARNING/ERROR）和**时间格式化**

**调用方式（任何地方）：**
```cpp
Logger::getInstance().log("操作信息");
Logger::getInstance().log("警告信息", LogLevel::WARNING);
```

### 4.2 设计模式二：CRTP 模式（Command）

**文件**: `include/Command.h` + `include/Commands.h`

**什么是 CRTP？**
CRTP（Curiously Recurring Template Pattern，奇异递归模板模式）是一种**静态多态**技术。派生类将自身作为模板参数传给基类。

**实现结构：**

```
CommandBase (纯虚基类，提供虚函数接口)
    │
    └── Command<Derived> (CRTP模板中间层)
            │
            ├── AddCommand     : Command<AddCommand>
            ├── DeleteCommand  : Command<DeleteCommand>
            ├── ListCommand    : Command<ListCommand>
            ├── UpdateCommand  : Command<UpdateCommand>
            ├── StatusCommand  : Command<StatusCommand>  (扩展)
            ├── CategoryCommand: Command<CategoryCommand>(扩展)
            ├── SearchCommand  : Command<SearchCommand>  (扩展)
            ├── FilterCommand  : Command<FilterCommand>  (扩展)
            └── StatsCommand   : Command<StatsCommand>   (扩展)
```

**核心代码：**

```cpp
// 第一层：纯虚基类（用于容器存储）
class CommandBase {
public:
    virtual void execute(const std::string& args) = 0;
    virtual ~CommandBase() = default;
};

// 第二层：CRTP模板（静态多态分发）
template <typename Derived>
class Command : public CommandBase {
public:
    void execute(const std::string& args) override {
        // 编译期确定调用哪个 Derived::executeImpl
        static_cast<Derived*>(this)->executeImpl(args);
    }
};

// 第三层：具体命令
class AddCommand : public Command<AddCommand> {
public:
    void executeImpl(const std::string& args) { /* 具体逻辑 */ }
};
```

**为什么同时使用 CommandBase 和 CRTP？**
- `CommandBase` 提供**运行时统一接口**，让 `std::unordered_map<string, unique_ptr<CommandBase>>` 可以存储不同命令
- `Command<Derived>` 提供**编译时静态分发**，`static_cast<Derived*>(this)->executeImpl()` 在编译期就确定了调用目标，编译器可以内联优化
- 这是"两全其美"的设计：既有容器统一管理的灵活性，又有 CRTP 的编译期优化

### 4.3 任务数据结构（Task）

**文件**: `include/Task.h`

Task 是一个结构体，包含：
- `id`: 唯一标识符（自增）
- `description`: 任务描述
- `priority`: 优先级（1 高/2 中/3 低）
- `dueDate`: 截止日期（YYYY-MM-DD 格式）
- `status`: 任务状态枚举（待办/进行中/已完成）—— **扩展新增**
- `category`: 分类标签 —— **扩展新增**

**序列化/反序列化**: 使用 `|` 分隔符将 Task 转为字符串存入文件，从文件读取时解析回 Task 对象。

```
文件格式示例（tasks.dat）:
1|完成毕业论文|1|2026-05-01|1|学业
2|购买实验材料|2|2026-04-15|0|实验
```

---

### 4.4 任务管理器（TaskManager）

**文件**: `include/TaskManager.h` + `src/TaskManager.cpp`

TaskManager 是核心业务逻辑层，负责：
1. **CRUD 操作**: 增删改查任务
2. **排序**: 支持 4 种排序方式（ID/优先级/日期/状态）
3. **搜索过滤**: 关键词搜索、按分类/状态/优先级过滤
4. **统计**: 生成任务统计面板
5. **持久化**: 自动将任务保存到 `tasks.dat` 文件

**数据流向：**
```
用户输入 → main.cpp解析 → Command.execute() → TaskManager方法
                                                    ↓
                                              操作 tasks vector
                                                    ↓
                                              saveTasks() → tasks.dat
                                              Logger记录 → log.txt
```

---

### 4.5 彩色输出系统（ColorOutput）

**文件**: `include/ColorOutput.h`

使用 ANSI 转义码实现终端彩色输出：
- 高优先级 → 红色
- 中优先级 → 黄色
- 低优先级 → 绿色
- 不同状态用不同颜色区分

这是一个纯头文件的工具模块，使用 `inline` 函数避免多重定义。

---

### 4.6 主程序入口（main. cpp）

**文件**: `src/main.cpp`

主程序的职责：
1. 创建 TaskManager 实例（构造时自动加载已有数据）
2. 创建所有命令对象，注册到 `unordered_map` 中
3. 进入主循环：读取输入 → 解析命令和参数 → 查表执行命令
4. 特殊处理 `help` 和 `exit` 命令

## 六、运行时生成的文件

- **tasks. dat**: 任务数据，每行一条任务，`|` 分隔字段

这两个文件在程序运行时自动创建，程序重启后数据自动恢复。

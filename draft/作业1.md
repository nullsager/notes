# 一、可以直接使用的题目

## 中文题目

**基于双量子比特门错误率的噪声感知 SABRE 量子线路映射算法**

## 英文题目

**Error-Aware SABRE Routing for Superconducting Quantum Architectures**

## 一句话概括

传统 SABRE 主要根据物理量子比特之间的拓扑距离选择 SWAP。本项目在其代价函数中加入物理耦合边的双量子比特门错误率，使算法在选择 SWAP 时尽量避开高错误率边，并从 SWAP 数、线路深度、编译时间和估计成功概率四方面评价算法。

# 二、为什么这个因素合理？

超导量子芯片上的物理量子比特一般不是全连接的。假设逻辑线路中需要执行：

```text
CX(q0, q3)
```

但是逻辑量子比特 `q0` 和 `q3` 当前所在的物理量子比特不相邻，就必须插入 SWAP。

传统 SABRE 主要考虑：

- SWAP 后，待执行量子门对应的两个量子比特是否更近；
- 对后续若干量子门是否也有帮助；
- 是否有利于并行执行。

但是它默认不同物理连接的质量近似相同。实际设备上，边之间的错误率可能差别很大。例如：

| 物理边 | 双量子比特门错误率 |
|---|---:|
| $p_0-p_1$ | $0.005$ |
| $p_1-p_2$ | $0.008$ |
| $p_2-p_5$ | $0.060$ |
| $p_4-p_5$ | $0.010$ |

最短路径可能经过错误率为 $0.060$ 的边，但稍微长一点的路径可能全部由低错误率边组成。

因此，“SWAP 数最少”不一定意味着“执行成功概率最高”。

这有明确参考依据。Murali 等人在 **Noise-Adaptive Compiler Mappings for Noisy Intermediate-Scale Quantum Computers** 中指出，使用设备校准数据并避开不可靠的量子比特和耦合边，可以显著提高程序成功率。

所以你不是凭空增加一个因素，而是：

> 将已有的噪声感知思想，以一种较简单的形式加入 SABRE 的局部 SWAP 选择中。

需要注意：不要声称“首次提出噪声感知映射”。你的创新点是**课程项目级的算法组合和实验分析**。

# 五、首先实现一个简化版 SABRE

## 5.1 建立线路依赖关系

把线路表示为有向无环图 DAG。

如果两个门作用在同一个逻辑量子比特上，它们必须保持原来的先后顺序。例如：

```text
H(q0)
CX(q0, q1)
CX(q0, q2)
```

第二个门必须等待第一个门完成，第三个门必须等待第二个门完成。

你可以为每个门保存：

```python
class Gate:
    def __init__(self, gate_id, name, qubits):
        self.gate_id = gate_id
        self.name = name
        self.qubits = tuple(qubits)
        self.predecessors = set()
        self.successors = set()
```

构建依赖关系的简单方法是记录每个逻辑量子比特上最近的一个门：

```python
def build_dependencies(gates, num_logical_qubits):
    last_gate = [None] * num_logical_qubits

    for gate in gates:
        for q in gate.qubits:
            if last_gate[q] is not None:
                pred = last_gate[q]
                gate.predecessors.add(pred.gate_id)
                pred.successors.add(gate.gate_id)

        for q in gate.qubits:
            last_gate[q] = gate
```

---

## 5.2 Front Layer

SABRE 中的 Front Layer 可以理解为：

> 当前所有前驱门都已经执行，可以立即考虑的门。

设 Front Layer 为 $F$。

如果 $F$ 中某个双量子比特门的两个逻辑量子比特已经映射到相邻物理量子比特，就执行这个门。

如果没有双量子比特门可以执行，就需要插入一个 SWAP。

---

## 5.3 映射关系

需要同时维护：

```python
logical_to_physical = {
    0: 0,
    1: 1,
    2: 2,
    3: 3,
}

physical_to_logical = {
    0: 0,
    1: 1,
    2: 2,
    3: 3,
    4: None,
    5: None,
    6: None,
    7: None,
    8: None,
}
```

在物理边 $(i,j)$ 上执行 SWAP 后，交换 `physical_to_logical[i]` 和 `physical_to_logical[j]`，然后更新反向映射。

---

## 5.4 候选 SWAP

不需要枚举所有硬件边。只枚举与 Front Layer 中逻辑量子比特当前位置相邻的硬件边。

例如 Front Layer 是：

```text
CX(q0, q3)
CX(q1, q2)
```

那么先找到 `q0`、`q1`、`q2`、`q3` 当前所在的物理位置，只考虑与这些物理位置关联的边。

```python
def generate_candidate_swaps(front_layer, mapping, hardware_graph):
    active_physical = set()

    for gate in front_layer:
        if len(gate.qubits) == 2:
            q1, q2 = gate.qubits
            active_physical.add(mapping[q1])
            active_physical.add(mapping[q2])

    candidates = set()

    for p in active_physical:
        for neighbor in hardware_graph.neighbors(p):
            candidates.add(tuple(sorted((p, neighbor))))

    return list(candidates)
```

这样实现简单，而且符合 SABRE 的局部搜索思想。

# 六、Baseline 代价函数

设逻辑量子比特到物理量子比特的映射为 $\pi$，物理耦合图上的最短跳数距离为 $D$。

对某个候选 SWAP $s$，先临时执行该 SWAP，得到新映射 $\pi_s$。

最基础的代价函数为：

$$
H_{\mathrm{basic}}(s)
=
\frac{1}{|F|}
\sum_{g\in F}
D\left(\pi_s(g.q_1),\pi_s(g.q_2)\right)
$$

距离越小越好。

## 加入 Look-Ahead

SABRE 还会考虑 Front Layer 后面的若干双量子比特门，形成 Extended Set $E$。

$$
H_{\mathrm{lookahead}}(s)
=
\frac{1}{|F|}
\sum_{g\in F}
D\left(\pi_s(g.q_1),\pi_s(g.q_2)\right)
+
W
\frac{1}{|E|}
\sum_{g\in E}
D\left(\pi_s(g.q_1),\pi_s(g.q_2)\right)
$$

其中：

- $F$ 是当前 Front Layer；
- $E$ 是后续若干双量子比特门；
- 建议令 $|E|=20$；
- 建议令 $W=0.5$。

你可以把所有距离除以硬件图直径，使代价值落在较稳定的范围内：

$$
\hat D(i,j)=\frac{D(i,j)}{D_{\max}}
$$

## 可选的 Decay

原始 SABRE 中还会通过 decay 因子避免连续选择作用在相同物理量子比特上的 SWAP：

$$
H_{\mathrm{SABRE}}(s)
=
\max\left(\mathrm{decay}(s.p_1),\mathrm{decay}(s.p_2)\right)
H_{\mathrm{lookahead}}(s)
$$

为了降低难度，你有两种选择：

- **推荐方案**：实现 look-ahead，不实现 decay，并明确称为“简化版 SABRE”；
- **加分方案**：最后再增加 decay。

不要因为追求完整复现而拖慢整个项目。

# 七、你的新增因素：双量子比特门错误率

## 7.1 将错误率转化为可累加代价

假设硬件边 $(i,j)$ 上双量子比特门的错误率为 $e_{ij}$，成功率为：

$$
r_{ij}=1-e_{ij}
$$

由于多个门的成功率通常以乘法形式组合，更适合使用负对数代价：

$$
c_{ij}=-\log(1-e_{ij})
$$

错误率越大，$c_{ij}$ 越大。

例如：

- 当 $e_{ij}=0.005$ 时，$c_{ij}$ 很小；
- 当 $e_{ij}=0.08$ 时，$c_{ij}$ 明显增大。

然后，在硬件图上使用 $c_{ij}$ 作为边权重，计算任意两个物理量子比特之间的加权最短路径距离：

$$
R(i,j)
=
\min_{P:i\rightarrow j}
\sum_{(u,v)\in P}c_{uv}
$$

这里的 $R(i,j)$ 可以理解为从 $i$ 到 $j$ 的近似“可靠性路径代价”。

为了与拓扑距离处于相似范围，再做归一化：

$$
\hat R(i,j)
=
\frac{R(i,j)}{R_{\max}}
$$

---

## 7.2 错误率感知的未来门代价

与拓扑距离类似，定义噪声代价：

$$
H_{\mathrm{error}}(s)
=
\frac{1}{|F|}
\sum_{g\in F}
\hat R\left(\pi_s(g.q_1),\pi_s(g.q_2)\right)
+
W
\frac{1}{|E|}
\sum_{g\in E}
\hat R\left(\pi_s(g.q_1),\pi_s(g.q_2)\right)
$$

它会让待交互的逻辑量子比特逐渐靠近可靠性较高的区域。

---

## 7.3 当前 SWAP 自身的错误代价

只考虑 SWAP 后的位置还不够，因为算法可能为了获得较好的未来位置，直接在一条高错误率边上执行 SWAP。

一个 SWAP 通常可以分解为三个 CX：

```text
CX(a, b)
CX(b, a)
CX(a, b)
```

因此，在边 $(i,j)$ 上执行 SWAP 的近似负对数错误代价为：

$$
C_{\mathrm{swap}}(i,j)=3c_{ij}
$$

归一化后可写成：

$$
\hat C_{\mathrm{swap}}(i,j)
=
\frac{c_{ij}}{c_{\max}}
$$

是否保留系数 $3$ 对排序影响不大，但在物理解释和最终 ESP 计算时应保留。

---

## 7.4 最终的新启发式函数

建议使用下面这个容易实现、容易解释的版本：

$$
H_{\mathrm{new}}(s)
=
(1-\alpha)H_{\mathrm{SABRE}}(s)
+
\alpha H_{\mathrm{error}}(s)
+
\beta \hat C_{\mathrm{swap}}(s)
$$

其中：

- $\alpha$ 控制未来可靠性的重要程度；
- $\beta$ 控制当前 SWAP 边错误率的重要程度。

Baseline 对应：

$$
\alpha=0,\qquad \beta=0
$$

建议实验参数：

$$
\alpha\in\{0,0.25,0.5,0.75,1.0\}
$$

$$
\beta\in\{0,0.1,0.25,0.5\}
$$

主实验可以先固定：

$$
\alpha=0.5,\qquad\beta=0.25
$$

然后做参数敏感性分析。

# 八、路由算法主流程

下面是你真正需要实现的核心逻辑。

```python
def route_circuit(
    gates,
    hardware_graph,
    hop_distance,
    error_distance,
    edge_error,
    initial_mapping,
    alpha=0.0,
    beta=0.0,
    lookahead_weight=0.5,
    extended_size=20,
):
    mapping = initial_mapping.copy()
    reverse_mapping = build_reverse_mapping(mapping, hardware_graph)

    front_layer = initialize_front_layer(gates)
    remaining_predecessors = initialize_predecessor_count(gates)

    executed = set()
    output_operations = []

    while len(executed) < len(gates):
        progress = False

        # 单量子比特门总是可以执行
        for gate in list(front_layer):
            if len(gate.qubits) == 1:
                q = gate.qubits[0]
                p = mapping[q]

                output_operations.append({
                    "name": gate.name,
                    "physical_qubits": [p],
                    "original_gate": gate.gate_id,
                })

                execute_gate_and_update_front_layer(
                    gate,
                    front_layer,
                    executed,
                    remaining_predecessors,
                    gates,
                )

                progress = True

        # 执行所有当前满足耦合约束的双量子比特门
        for gate in list(front_layer):
            if len(gate.qubits) != 2:
                continue

            q1, q2 = gate.qubits
            p1 = mapping[q1]
            p2 = mapping[q2]

            if hardware_graph.has_edge(p1, p2):
                output_operations.append({
                    "name": gate.name,
                    "physical_qubits": [p1, p2],
                    "original_gate": gate.gate_id,
                })

                execute_gate_and_update_front_layer(
                    gate,
                    front_layer,
                    executed,
                    remaining_predecessors,
                    gates,
                )

                progress = True

        if progress:
            continue

        # 没有门可以执行，必须插入 SWAP
        candidates = generate_candidate_swaps(
            front_layer,
            mapping,
            hardware_graph,
        )

        extended_set = get_extended_set(
            gates,
            executed,
            front_layer,
            max_size=extended_size,
        )

        best_swap = None
        best_cost = float("inf")

        for swap_edge in candidates:
            temp_mapping = apply_swap_copy(
                mapping,
                reverse_mapping,
                swap_edge,
            )

            cost = calculate_heuristic(
                swap_edge=swap_edge,
                temp_mapping=temp_mapping,
                front_layer=front_layer,
                extended_set=extended_set,
                hop_distance=hop_distance,
                error_distance=error_distance,
                edge_error=edge_error,
                alpha=alpha,
                beta=beta,
                lookahead_weight=lookahead_weight,
            )

            if cost < best_cost:
                best_cost = cost
                best_swap = swap_edge

        apply_swap_in_place(
            mapping,
            reverse_mapping,
            best_swap,
        )

        output_operations.append({
            "name": "swap",
            "physical_qubits": list(best_swap),
            "heuristic_cost": best_cost,
        })

    return {
        "operations": output_operations,
        "final_mapping": mapping,
    }
```

## 代价函数实现框架

```python
import math


def average_pair_cost(gates, mapping, distance_matrix):
    if not gates:
        return 0.0

    total = 0.0

    for gate in gates:
        if len(gate.qubits) != 2:
            continue

        q1, q2 = gate.qubits
        p1 = mapping[q1]
        p2 = mapping[q2]

        total += distance_matrix[p1][p2]

    return total / max(len(gates), 1)


def calculate_heuristic(
    swap_edge,
    temp_mapping,
    front_layer,
    extended_set,
    hop_distance,
    error_distance,
    edge_error,
    alpha,
    beta,
    lookahead_weight,
):
    topology_cost = (
        average_pair_cost(
            front_layer,
            temp_mapping,
            hop_distance,
        )
        + lookahead_weight
        * average_pair_cost(
            extended_set,
            temp_mapping,
            hop_distance,
        )
    )

    reliability_cost = (
        average_pair_cost(
            front_layer,
            temp_mapping,
            error_distance,
        )
        + lookahead_weight
        * average_pair_cost(
            extended_set,
            temp_mapping,
            error_distance,
        )
    )

    edge = tuple(sorted(swap_edge))
    max_error = max(edge_error.values())
    immediate_swap_cost = edge_error[edge] / max_error

    return (
        (1.0 - alpha) * topology_cost
        + alpha * reliability_cost
        + beta * immediate_swap_cost
    )
```

实际实现时，`hop_distance` 和 `error_distance` 应预先归一化。

# 九、如何计算评价指标？

swap_count = sum(

## 9.2 双量子比特门数量

如果一个 SWAP 分解为三个 CX，则：

$$
N_{\mathrm{2Q}}
=
N_{\mathrm{original\ 2Q}}
+
3N_{\mathrm{SWAP}}
$$

```python
def count_two_qubit_gates(operations):
    total = 0

    for op in operations:
        if op["name"] == "swap":
            total += 3
        elif len(op["physical_qubits"]) == 2:
            total += 1

    return total
```

## 9.3 线路深度

可以用一个简单的 ASAP 调度计算。

为每个物理量子比特记录其上一个操作结束的时间：

```python
def estimate_depth(operations, num_physical_qubits):
    last_time = [0] * num_physical_qubits

    for op in operations:
        qubits = op["physical_qubits"]

        if op["name"] == "swap":
            duration = 3
        else:
            duration = 1

        start = max(last_time[q] for q in qubits)
        end = start + duration

        for q in qubits:
            last_time[q] = end

    return max(last_time)
```

这里把单量子比特门和普通双量子比特门时长都近似为 $1$，SWAP 时长近似为 $3$。

如果时间充足，可以设置：

- 单量子比特门时长为 $1$；
- 双量子比特门时长为 $5$；
- SWAP 时长为 $15$。

但所有算法必须使用相同定义。

## 9.4 估计成功概率 ESP

如果某条边 $(i,j)$ 上执行了 $n_{ij}$ 个双量子比特门，其错误率为 $e_{ij}$，则双量子比特门部分的估计成功概率为：

$$
\mathrm{ESP}_{2Q}
=
\prod_{(i,j)}
(1-e_{ij})^{n_{ij}}
$$

对于在边 $(i,j)$ 上执行的一个 SWAP，需要计为三个双量子比特门：

$$
\mathrm{ESP}_{\mathrm{SWAP}(i,j)}
=
(1-e_{ij})^3
$$

实际计算建议使用对数，防止数值下溢：

$$
\log\mathrm{ESP}_{2Q}
=
\sum_{(i,j)}
n_{ij}\log(1-e_{ij})
$$

```python
def calculate_log_esp(operations, edge_error):
    log_esp = 0.0

    for op in operations:
        if len(op["physical_qubits"]) != 2:
            continue

        p1, p2 = op["physical_qubits"]
        edge = tuple(sorted((p1, p2)))
        error = edge_error[edge]

        repetitions = 3 if op["name"] == "swap" else 1
        log_esp += repetitions * math.log(1.0 - error)

    return log_esp
```

需要在论文里明确：

> ESP 是基于独立门错误假设得到的近似指标，并不等于真实硬件保真度。

## 10.2 硬件错误模型

建议做三类实验。

### 实验 A：均匀错误率

所有边错误率相同：

$$
e_{ij}=0.01
$$

预期结果：

- Baseline 和新算法结果应接近；
- 如果差异很大，说明归一化或实现可能有问题。

这是一个非常重要的正确性检查。

### 实验 B：固定异构错误率

人为设置少数坏边：

- 普通边错误率：$0.005$ 到 $0.015$；
- 坏边错误率：$0.05$ 到 $0.08$。

这个实验方便画出路径案例图，解释算法为什么绕路。

### 实验 C：随机异构错误率

固定硬件拓扑，使用多个随机种子生成错误率：

```python
import random


def generate_edge_errors(edges, seed):
    rng = random.Random(seed)
    result = {}

    for edge in edges:
        if rng.random() < 0.2:
            error = rng.uniform(0.04, 0.08)
        else:
            error = rng.uniform(0.004, 0.02)

        result[tuple(sorted(edge))] = error

    return result
```

建议：

- 每条线路使用 $10$ 个错误率种子；
- 如果加入随机初始映射，再使用 $5$ 个映射种子；
- 总运行数不用特别大，因为算法运行很快。

# 十一、怎样判断新算法“更好还是更坏”？

不要只给出一个“新算法更好”的结论。你应该从多个指标分析。

## 11.1 主要评价目标

推荐将可靠性作为主要目标：

$$
\Delta\log\mathrm{ESP}
=
\log\mathrm{ESP}_{\mathrm{new}}
-
\log\mathrm{ESP}_{\mathrm{baseline}}
$$

如果：

$$
\Delta\log\mathrm{ESP}>0
$$

说明新算法估计成功概率更高。

也可以报告 ESP 提升倍数：

$$
\mathrm{ESP\ Ratio}
=
\frac{\mathrm{ESP}_{\mathrm{new}}}
{\mathrm{ESP}_{\mathrm{baseline}}}
=
\exp(\Delta\log\mathrm{ESP})
$$

---

## 11.2 代价指标

同时报告：

$$
\Delta N_{\mathrm{SWAP}}
=
N_{\mathrm{SWAP,new}}
-
N_{\mathrm{SWAP,base}}
$$

$$
\Delta \mathrm{Depth}
=
\mathrm{Depth}_{\mathrm{new}}
-
\mathrm{Depth}_{\mathrm{base}}
$$

$$
\Delta T
=
T_{\mathrm{new}}
-
T_{\mathrm{base}}
$$

---

## 11.3 最可能得到的结论

你的最终结论很可能是：

> 在错误率均匀时，噪声感知因子没有明显优势；在错误率异构时，新算法倾向于避开高错误率边，能够提高 ESP，但部分线路会增加 SWAP 数和线路深度。因此，它不是在所有指标上都优于传统 SABRE，而是在可靠性目标下表现更好，并形成可靠性与线路开销之间的权衡。

这是一个非常合理、也很符合老师题目要求的结论。

如果实验出现下面的结果，也完全可以接受：

| 指标 | 变化 |
|---|---|
| ESP | 提高 |
| SWAP 数 | 增加 |
| 深度 | 增加 |
| 编译时间 | 略微增加 |

这说明新增因素确实起作用，但有代价。

如果 ESP 反而下降，可以分析：

1. $\alpha$ 或 $\beta$ 太大；
2. 算法为了避开坏边插入了过多 SWAP；
3. 局部启发式只看到有限的未来门；
4. 加权最短路径不能准确预测最终线路；
5. 固定初始映射限制了算法效果。

“新增因素导致部分指标变坏”并不代表作业失败，反而能体现启发式算法不一定全面合理。

# 十五、容易踩的坑

## 1. 不要直接修改 Qiskit 的 SABRE 源码

当前 Qiskit 的 SABRE 实现包含优化后的底层实现，直接修改内部代码反而提高难度。课程作业应自己实现一个简化版本。

Qiskit 的 `SabreSwap` 可以作为结果对照，但不要把它当成必须修改的框架。

## 2. 不要一开始就上真机

真机存在：

- 排队；
- Token；
- 校准数据变化；
- 运行次数限制；
- 结果噪声；
- 软件版本问题。

先用模拟错误率完成全部工作。真机或 Fake Backend 只作为加分项。

## 3. Baseline 和新算法必须使用相同输入

包括：

- 相同线路；
- 相同硬件拓扑；
- 相同错误率；
- 相同初始映射；
- 相同随机种子；
- 相同 tie-breaking 方式。

否则比较不公平。

## 4. 不要把 ESP 称为真实保真度

ESP 只是近似评价指标。正确说法是：

> Estimated Success Probability under the independent gate error assumption。

## 5. 不要只选一个手工案例

手工案例可以用于解释，但正式结论至少应来自：

- 多条线路；
- 多组错误率；
- 多个随机种子。

## 6. 不要为了 ESP 无限绕路

这正是为什么需要同时保留拓扑距离项。若令 $\alpha=1$ 且 $\beta$ 很大，算法可能为了避开一条坏边而插入大量 SWAP，最终反而降低 ESP。

- 在至少 $6$ 条线路、多个错误率种子上实验；
- 分析可靠性与线路开销的权衡。

## 加分内容

有余力再做：

- decay；
- 随机初始映射；
- $\alpha$、$\beta$ 参数扫描；
- Qiskit `SabreSwap` 对照；
- 实际 IBM Fake Backend 校准数据；
- 噪声模拟器验证 ESP 与实际输出保真度的相关性。

最关键的是：**先完成简化、可运行、可复现的版本，再做加分项。** 这个选题实现难度低、理论依据充分，也非常贴合题目所要求的“增加启发式因素，并分析算法变好还是变坏”。

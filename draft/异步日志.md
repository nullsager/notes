## 1. 项目概述

### 这个项目是什么？

AsyncLog 是一个**高性能异步日志系统**，用 C++20 编写。

**日志系统**就是程序运行时的"黑匣子"——它把程序的运行状态、错误信息、调试信息等记录到文件里，方便开发者排查问题。你在手机 App 崩溃时看到的"发送崩溃报告"，背后就是日志系统在工作。

**为什么要"异步"？** 想象一下：你的程序每秒要处理 10 万个请求，如果每次打日志都要等文件写入完成才能继续，程序就会变得很慢。异步日志的做法是：**主线程只管把日志消息"扔"到一个队列里就继续干活，另一个专门的后台线程负责从队列里取出消息写入文件**。这样主线程几乎不受影响。

### 这个项目的学习目标

| 技术点 | 说明 |
|--------|------|
| 可变参数模板 (Variadic Templates) | 让函数接受任意数量、任意类型的参数 |
| 折叠表达式 (Fold Expression) | C++17 的语法糖，一行代码展开参数包 |
| 无锁数据结构 (Lock-Free Queue) | 不用互斥锁就能实现线程安全的队列 |
| 多线程编程 | 生产者-消费者模型、原子操作、内存序 |
| 模板元编程 | 编译期日志级别过滤，实现零开销 |
| RAII 资源管理 | 析构函数自动清理线程和文件 |

## 3. 核心概念科普

在看代码之前，先理解几个关键概念。

### 3.1 日志级别

日志不是所有信息都一样重要。日志系统用"级别"来区分：

| 级别 | 数值 | 含义 | 举例 |
|------|------|------|------|
| DEBUG | 0 | 调试信息，开发时用 | "变量 x 的值是 42" |
| INFO | 1 | 正常运行信息 | "服务器启动成功" |
| WARN | 2 | 警告，可能有问题 | "磁盘使用率 85%" |
| ERROR | 3 | 错误，功能受损 | "数据库连接失败" |
| FATAL | 4 | 致命错误，程序要挂了 | "内存不足" |
| OFF | 5 | 关闭所有日志 | — |

**过滤规则：** 设置最低级别为 WARN，则 DEBUG 和 INFO 的日志都不会输出，只有 WARN、ERROR、FATAL 会输出。

### 3.2 生产者-消费者模型

```
[线程A]  ──写日志──→  ┌─────────┐  ──→  [后台线程]  ──→  文件
[线程B]  ──写日志──→  │  队 列   │  ──→  [后台线程]  ──→  文件
[线程C]  ──写日志──→  └─────────┘
    ↑ 生产者                                ↑ 消费者
```

- **生产者**：调用 `logger.info()` 的线程，把日志消息放入队列
- **消费者**：后台线程，从队列取出消息写入文件
- **队列**：生产者和消费者之间的"传送带"

### 3.3 无锁 vs 有锁

**有锁（Mutex）方案：**
```
线程A 想写队列 → 加锁 → 写入 → 解锁
线程B 想写队列 → 发现锁被占 → 等待（阻塞） → 加锁 → 写入 → 解锁
```
问题：线程 B 必须等线程 A 完成，等待过程涉及操作系统的上下文切换（约 1~10 微秒）。

**无锁（Lock-Free）方案：**
```
线程A 想写队列 → CAS 操作 → 成功 → 写入
线程B 想写队列 → CAS 操作 → 失败（被A抢了） → 重试 → 成功 → 写入
```
CAS（Compare-And-Swap）是 CPU 级别的原子指令，耗时仅纳秒级，不需要操作系统介入。

### 3.4 CAS（Compare-And-Swap）原子操作

CAS 是无锁编程的基石。它做的事情是：

```
CAS(内存位置, 期望值, 新值):
    如果 内存位置的当前值 == 期望值:
        把内存位置设为新值
        返回 true（成功）
    否则:
        返回 false（失败，说明别人已经改了）
```

这是一条 **CPU 硬件指令**，保证了原子性（不会被其他线程打断）。

## 4. 代码逐文件详解

### 4.1 LogLevel. h -- 日志级别

这是最简单的文件，定义了日志级别。

```cpp
// 日志级别枚举，数值越大优先级越高
enum class LogLevel : uint8_t {
    DEBUG = 0,
    INFO  = 1,
    WARN  = 2,
    ERROR = 3,
    FATAL = 4,
    OFF   = 5   // 用于关闭所有日志
};
```

**要点解析：**

1. **`enum class`**：C++11 引入的强类型枚举。和普通 `enum` 的区别是不会隐式转换为 int，必须写 `LogLevel::DEBUG` 而不能直接写 `DEBUG`，避免命名冲突。

2. **`: uint8_t`**：指定底层存储类型为 8 位无符号整数（0~255），节省内存。

3. **数值递增设计**：DEBUG=0 到 FATAL=4，**数值越大优先级越高**。过滤时只需要比较 `if (level >= min_level)`。

```cpp
// 将日志级别转换为固定宽度的字符串标签
constexpr std::string_view logLevelToString(LogLevel level) {
    switch (level) {
        case LogLevel::DEBUG: return "DEBUG";
        case LogLevel::INFO:  return "INFO ";  // 注意后面有空格，对齐用
        case LogLevel::WARN:  return "WARN ";
        case LogLevel::ERROR: return "ERROR";
        case LogLevel::FATAL: return "FATAL";
        default:              return "?????";
    }
}
```

**要点：** `constexpr` 表示这个函数可以在**编译期**执行。`string_view` 是 C++17 引入的轻量字符串视图，不拥有内存，只是一个指针+长度，比 `std::string` 零开销。

```cpp
#ifndef ASYNCLOG_COMPILE_LEVEL
#define ASYNCLOG_COMPILE_LEVEL 0  // 默认: DEBUG，不过滤任何级别
#endif

// 编译期检查
template <LogLevel Level>
constexpr bool isLevelEnabled() {
    return static_cast<uint8_t>(Level) >= ASYNCLOG_COMPILE_LEVEL;
}
```

**这段代码做了什么？**

编译期日志过滤。比如你设置 `ASYNCLOG_COMPILE_LEVEL=2`（WARN），那么：
- `isLevelEnabled<LogLevel::DEBUG>()` → `0 >= 2` → `false`
- `isLevelEnabled<LogLevel::WARN>()` → `2 >= 2` → `true`

配合后面 Logger. h 中的 `if constexpr`，编译器会直接**删除** DEBUG 和 INFO 的代码，连一条指令都不会生成。这就是"零开销"的含义。

### 4.2 Formatter. h -- 格式化引擎

这个文件实现了类似 Python `f-string` 或 `fmt` 库的功能：用 `{}` 做占位符。

#### toString 函数：把任意类型转成字符串

```cpp
template <typename T>
std::string toString(T&& arg) {
    // 如果已经是 string，直接返回（完美转发，避免拷贝）
    if constexpr (std::is_same_v<std::decay_t<T>, std::string>) {
        return std::forward<T>(arg);
    }
    // 如果是 C 字符串（const char*），构造 string
    else if constexpr (std::is_same_v<std::decay_t<T>, const char*> ||
                       std::is_same_v<std::decay_t<T>, char*>) {
        return std::string(arg);
    }
    // 如果是 string_view，构造 string
    else if constexpr (std::is_same_v<std::decay_t<T>, std::string_view>) {
        return std::string(arg);
    }
    // 其他类型（int, double 等），用 ostringstream 转换
    else {
        std::ostringstream oss;
        oss << std::forward<T>(arg);
        return oss.str();
    }
}
```

**逐行解析：**

- **`template <typename T>`**：模板函数，T 可以是任何类型（int, string, double...）
- **`T&& arg`**：万能引用（Universal Reference），既能接受左值也能接受右值
- **`if constexpr`**：C++17 编译期 if。和普通 if 的区别是：**不满足条件的分支在编译时直接被删除**，不会产生任何代码
- **`std::decay_t<T>`**：去掉引用和 const 修饰，获取"本来的类型"。比如 `const string&` 变成 `string`
- **`std::is_same_v<A, B>`**：编译期判断 A 和 B 是不是同一类型
- **`std::forward<T>(arg)`**：完美转发，保持参数的左值/右值属性，避免不必要的拷贝

#### format 函数：替换 {} 占位符

```cpp
template <typename... Args>
std::string format(std::string_view fmt, Args&&... args) {
    if constexpr (sizeof...(args) == 0) {
        return std::string(fmt);  // 没有参数，直接返回格式字符串
    } else {
        // 折叠表达式：一次性把所有参数转成字符串数组
        std::vector<std::string> arg_strings = {toString(std::forward<Args>(args))...};
        // ... 查找 {} 并替换 ...
    }
}
```

**关键技术 -- 折叠表达式（Fold Expression）：**

```cpp
std::vector<std::string> arg_strings = {toString(std::forward<Args>(args))...};
```

这一行等价于（假设有 3 个参数 a, b, c）：

```cpp
std::vector<std::string> arg_strings = {
    toString(std::forward<Arg1>(a)),
    toString(std::forward<Arg2>(b)),
    toString(std::forward<Arg3>(c))
};
```

`...` 是参数包展开操作符，编译器会自动展开为多个调用。

**format 的三种情况：**

```
format("{} + {} = {}", 1, 2, 3)     → "1 + 2 = 3"      （正好匹配）
format("{} {} {}", "only")          → "only {} {}"       （占位符多，保留多余的 {}）
format("{}", "a", "b", "c")         → "a b c"            （参数多，空格追加多余参数）
```

### 4.3 LockFreeQueue. h -- 无锁队列

这是项目中**最核心、最有技术含量**的组件，实现了 Dmitry Vyukov 的有界 MPMC（多生产者多消费者）无锁队列。

#### 数据结构

```cpp
template <typename T>
class LockFreeQueue {
private:
    struct Cell {
        std::atomic<size_t> sequence;  // 序列号（标记槽位状态）
        T data;                        // 实际数据
    };

    alignas(64) std::atomic<size_t> enqueue_pos_;  // 入队位置
    alignas(64) std::atomic<size_t> dequeue_pos_;  // 出队位置
    std::vector<Cell> buffer_;                     // 环形缓冲区
    size_t mask_;                                  // 容量-1，用于位运算取模
};
```

**想象成一个环形传送带：**

```
           enqueue_pos_ = 5（下一个入队位置）
                ↓
    ┌───┬───┬───┬───┬───┬───┬───┬───┐
    │ D │ D │ D │ E │ E │   │   │   │
    └───┴───┴───┴───┴───┴───┴───┴───┘
      0   1   2   3   4   5   6   7
                ↑
           dequeue_pos_ = 3（下一个出队位置）

    D = 已读取（空闲）  E = 有数据  空白 = 从未使用
```

**`alignas(64)` 的作用 -- 防止 false sharing：**

CPU 缓存以 64 字节为单位（一条 cache line）读写内存。如果 `enqueue_pos_` 和 `dequeue_pos_` 挨着存在同一条 cache line 里：

```
[cache line: enqueue_pos_ | dequeue_pos_ | ...]
```

线程 A 修改 `enqueue_pos_` → 整条 cache line 失效 → 线程 B 要重新从内存加载 `dequeue_pos_`，即使 `dequeue_pos_` 根本没变！这就是 **false sharing**，严重影响性能。

加了 `alignas(64)` 后，两个变量各占一条 cache line，互不干扰。

**容量为什么必须是 2 的幂？**

```cpp
// 用位掩码代替取模
size_t index = pos & mask_;    // mask_ = capacity - 1

// 等价于（但快得多）
size_t index = pos % capacity;
```

位运算（AND）只需 1 个 CPU 周期，而除法/取模需要 ~30 个周期。当容量是 2 的幂时（如 8 = 0 b 1000），`capacity - 1 = 7 = 0b0111`，AND 运算自然实现了取模：

```
pos = 13 = 0b1101
mask = 7 = 0b0111
13 & 7   = 0b0101 = 5  ← 等价于 13 % 8 = 5
```

#### tryPush 入队操作（详解）

```cpp
bool tryPush(const T& data) {
    Cell* cell;
    size_t pos = enqueue_pos_.load(std::memory_order_relaxed);

    for (;;) {  // CAS 重试循环
        cell = &buffer_[pos & mask_];  // 计算目标槽位
        size_t seq = cell->sequence.load(std::memory_order_acquire);
        intptr_t diff = static_cast<intptr_t>(seq) - static_cast<intptr_t>(pos);

        if (diff == 0) {
            // seq == pos：槽位空闲，尝试 CAS 抢占 enqueue_pos_
            if (enqueue_pos_.compare_exchange_weak(pos, pos + 1,
                    std::memory_order_relaxed)) {
                break;  // CAS 成功，我抢到了这个位置
            }
            // CAS 失败：其他线程抢先了，pos 被自动更新为最新值，继续循环
        } else if (diff < 0) {
            return false;  // 队列满了（该槽位的数据还没被消费者读走）
        } else {
            // diff > 0：其他生产者正在写这个槽位，刷新 pos 重试
            pos = enqueue_pos_.load(std::memory_order_relaxed);
        }
    }

    // 到这里，我们独占了 cell，可以安全写入数据
    cell->data = data;
    // release：确保 data 写入对消费者可见（"发布"这条数据）
    cell->sequence.store(pos + 1, std::memory_order_release);
    return true;
}
```

**序列号状态机：**

每个槽位的 `sequence` 值表示它的状态：

| 阶段 | sequence 值 | 含义 |
|------|------------|------|
| 初始 | `i`（等于索引） | 空闲，可写 |
| 写入后 | `pos + 1` | 有数据，可读 |
| 读取后 | `pos + capacity` | 空闲，回到下一轮可写 |

**内存序（Memory Ordering）解释：**

这是最难理解的部分。CPU 和编译器会对指令重排序以提高性能，内存序用来控制这种重排序。

- **`relaxed`**：最弱的保证，只保证操作是原子的，不保证其他线程能看到。用于 `enqueue_pos_` 的读取，因为即使读到旧值也没关系（CAS 会纠正）。
- **`acquire`**（获取）：读操作使用。保证"我在 acquire 之后的读写，不会被重排到 acquire 之前"。读 sequence 时用，确保能看到生产者写入的 data。
- **`release`**（释放）：写操作使用。保证"我在 release 之前的读写，不会被重排到 release 之后"。写 sequence 时用，确保 data 已经写完才标记为"有数据"。

**简单理解：`release` 是"发布"，`acquire` 是"接收"。发布保证数据已准备好，接收保证能看到发布的数据。**

#### tryPop 出队操作

```cpp
bool tryPop(T& data) {
    Cell* cell;
    size_t pos = dequeue_pos_.load(std::memory_order_relaxed);

    for (;;) {
        cell = &buffer_[pos & mask_];
        size_t seq = cell->sequence.load(std::memory_order_acquire);
        intptr_t diff = static_cast<intptr_t>(seq) - static_cast<intptr_t>(pos + 1);

        if (diff == 0) {
            // seq == pos+1：数据就绪
            if (dequeue_pos_.compare_exchange_weak(pos, pos + 1,
                    std::memory_order_relaxed)) {
                break;
            }
        } else if (diff < 0) {
            return false;  // 队列空
        } else {
            pos = dequeue_pos_.load(std::memory_order_relaxed);
        }
    }

    data = std::move(cell->data);  // 移动语义，避免拷贝
    // 标记槽位为空闲：sequence = pos + capacity（下一轮的起始值）
    cell->sequence.store(pos + mask_ + 1, std::memory_order_release);
    return true;
}
```

**完整的一次入队-出队生命周期（以容量 4 为例）：**

```
初始状态：
  slot[0].seq=0, slot[1].seq=1, slot[2].seq=2, slot[3].seq=3
  enqueue_pos_=0, dequeue_pos_=0

Push(A) 到 slot[0]：
  1. pos=0, slot[0].seq=0, diff=0-0=0 → CAS 成功
  2. slot[0].data = A
  3. slot[0].seq = 0+1 = 1 (release)
  → enqueue_pos_=1

Pop() 从 slot[0]：
  1. pos=0, slot[0].seq=1, diff=1-(0+1)=0 → CAS 成功
  2. data = A
  3. slot[0].seq = 0+3+1 = 4 (release)   ← 4 = pos + capacity
  → dequeue_pos_=1

下一轮 Push 到 slot[0]：
  1. pos=4, slot[0].seq=4, diff=4-4=0 → 可以写入
  （pos=4, 4 & mask=4&3=0, 所以写到 slot[0]）
```

### 4.4 Logger. h -- 核心日志类

这是最大的文件，整合了所有组件。

#### FormatWithLocation -- 自动捕获调用位置的巧妙设计

```cpp
struct FormatWithLocation {
    std::string_view fmt;
    std::source_location loc;

    // 注意：没有 explicit！
    FormatWithLocation(const char* fmt,
                       const std::source_location& loc = std::source_location::current())
        : fmt(fmt), loc(loc) {}
};
```

**为什么需要这个结构体？**

我们希望日志能自动记录"是在哪个文件、哪一行调用的"：

```
[2024-04-05 11:30:45] [INFO ] [main.cpp:15] 应用程序启动
                                ↑ 这个信息怎么来的？
```

`std::source_location::current()` 能获取调用点的文件名和行号，但它必须作为**默认参数**才能在调用点求值。问题是：

```cpp
// 这样写行不通！参数包 Args... 必须在最后
template <typename... Args>
void info(string_view fmt, Args&&... args,
          source_location loc = source_location::current());  // ❌ 编译错误
```

**解决方案：** 把 fmt 和 loc 包装在一个结构体里，利用**隐式转换**（构造函数没有 `explicit`）：

```cpp
logger.info("hello");
// 编译器看到的：
// logger.info(FormatWithLocation("hello", source_location::current()));
// source_location::current() 在调用者（main.cpp:15）的上下文中求值
```

这个技巧来自 spdlog 和 fmt 库，是业界通用的做法。

#### 构造函数

```cpp
explicit Logger(const std::string& filename,
                LogLevel min_level = LogLevel::DEBUG,
                bool console_output = true,
                size_t max_file_size = 10 * 1024 * 1024,  // 10MB
                size_t queue_capacity = 8192)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `filename` | 必填 | 日志文件路径 |
| `min_level` | DEBUG | 运行时最低日志级别 |
| `console_output` | true | 是否同时在终端输出 |
| `max_file_size` | 10 MB | 单个文件最大体积，超出自动轮转 |
| `queue_capacity` | 8192 | 无锁队列容量（必须是 2 的幂） |

构造函数做了三件事：
1. 打开日志文件（追加模式）
2. 记录当前文件大小（用于轮转判断）
3. **启动后台消费者线程**

#### log 核心方法 -- 双重过滤

```cpp
template <LogLevel Level, typename... Args>
void log(FormatWithLocation fmt_loc, Args&&... args) {
    // 第一层：编译期过滤（if constexpr）
    if constexpr (isLevelEnabled<Level>()) {
        // 第二层：运行时过滤
        if (Level < min_level_) {
            return;
        }

        // 格式化消息
        std::string formatted = format(fmt_loc.fmt, std::forward<Args>(args)...);
        // 构建完整日志行（加时间戳、级别、位置）
        std::string full_msg = buildLogLine(Level, fmt_loc.loc, formatted);

        // 入队（如果队列满就自旋等待）
        while (!queue_.tryPush(LogEntry{Level, std::move(full_msg)})) {
            std::this_thread::yield();
        }
    }
}
```

**两层过滤的区别：**

| | 编译期过滤 (`if constexpr`) | 运行时过滤 (`if (Level < min_level_)`) |
|---|---|---|
| 设置方式 | CMake: `-DASYNCLOG_COMPILE_LEVEL=2` | 代码: `logger.setLevel(LogLevel::WARN)` |
| 开销 | 零开销（代码被删除） | 极低（一次比较，<1 ns） |
| 灵活性 | 改了要重新编译 | 随时可改 |
| 用途 | 发布版去除所有 DEBUG | 运行中动态调整 |

**便捷方法：**

```cpp
template <typename... Args>
void info(FormatWithLocation fmt, Args&&... args) {
    log<LogLevel::INFO>(fmt, std::forward<Args>(args)...);
}
// 同理还有 debug(), warn(), error(), fatal()
```

#### 后台消费者线程 -- 批量刷盘

```cpp
void processQueue() {
    std::vector<LogEntry> batch;
    batch.reserve(256);  // 预分配空间，减少 vector 扩容

    while (true) {
        // 1. 批量取出：一口气从队列里取出所有可用消息
        LogEntry entry;
        while (queue_.tryPop(entry)) {
            batch.push_back(std::move(entry));
        }

        if (!batch.empty()) {
            // 2. 批量写入文件 + 控制台
            for (const auto& e : batch) {
                writeEntry(e);
            }
            log_file_.flush();  // 只 flush 一次，不是每条都 flush
            batch.clear();
        } else if (stop_flag_.load(std::memory_order_acquire)) {
            // 3. 收到停止信号，做最后一次排空
            while (queue_.tryPop(entry)) {
                writeEntry(entry);
            }
            log_file_.flush();
            break;
        } else {
            // 4. 队列空且未停止，休眠 1ms 避免 CPU 空转
            std::this_thread::sleep_for(std::chrono::milliseconds(1));
        }
    }
}
```

**为什么要批量？**

每次 `flush()` 都是一个系统调用（涉及内核态切换），开销约 1~10 微秒。如果每条日志都 flush，10 万条日志就要 10 万次 flush。批量取出 100 条一起 flush，系统调用次数减少 100 倍。

#### 日志文件轮转

```cpp
void rotateFile() {
    log_file_.close();
    file_index_++;

    // 把 "log.txt" 拆分为 stem="log" 和 ext=".txt"
    // 新文件名：log.1.txt, log.2.txt, ...
    std::string new_filename = stem + "." + std::to_string(file_index_) + ext;
    log_file_.open(new_filename, std::ios::out | std::ios::app);
    current_file_size_ = 0;
}
```

当日志文件超过 `max_file_size`（默认 10 MB）时，自动关闭当前文件，创建新文件。

#### 析构函数 -- RAII 保证资源清理

```cpp
~Logger() {
    stop_flag_.store(true, std::memory_order_release);  // 通知后台线程停止
    if (worker_thread_.joinable()) {
        worker_thread_.join();  // 等待后台线程处理完所有剩余日志
    }
    if (log_file_.is_open()) {
        log_file_.close();  // 关闭文件
    }
}
```

**RAII（Resource Acquisition Is Initialization）：** Logger 对象销毁时自动清理所有资源（线程、文件），不需要手动调用 close () 或 stop ()。这是 C++ 最重要的编程范式之一。

### 4.5 src/main. cpp -- 演示程序

```cpp
int main() {
    try {
        // 创建日志器
        Logger logger("log.txt", LogLevel::DEBUG, true);

        // 1. 各级别日志
        logger.info("应用程序启动。");
        logger.debug("调试信息：变量 x = {}, y = {}", 100, 200);
        logger.warn("警告：磁盘使用率已达 {}%", 85);
        logger.error("错误：无法连接到数据库 {}", "db-server-01");
        logger.fatal("致命错误：系统内存不足，仅剩 {}MB", 12);

        // 2. 格式化测试
        logger.info("用户 {} 执行了 {} 操作，耗时 {} 秒。", 42, "login", 3.5);
        logger.warn("占位符多于参数：{} {} {}", "only_one");
        logger.info("参数多于占位符：{}", "first", "second", "third");

        // 3. 运行时级别过滤
        logger.setLevel(LogLevel::WARN);
        logger.debug("这条不会出现");  // 被过滤
        logger.warn("这条会出现");     // 通过

        // 4. 多线程并发
        logger.setLevel(LogLevel::DEBUG);
        std::vector<std::thread> threads;
        for (int i = 0; i < 5; i++) {
            threads.emplace_back([&logger, i]() {
                for (int j = 0; j < 20; j++) {
                    logger.info("线程 {} 日志 #{}", i, j);
                }
            });
        }
        for (auto& t : threads) t.join();

    } catch (const std::exception& ex) {
        std::cerr << "日志系统初始化失败: " << ex.what() << std::endl;
    }
    return 0;
}
```

## 5. 整体架构与数据流

### 完整的日志处理流程

```
用户调用 logger.info("hello {}", "world")
                    │
                    ▼
    ┌─── FormatWithLocation 隐式构造 ───┐
    │   捕获 source_location（文件名:行号） │
    └───────────────────────────────────┘
                    │
                    ▼
    ┌─── 编译期过滤 (if constexpr) ───┐
    │   ASYNCLOG_COMPILE_LEVEL=2?     │
    │   INFO(1) < 2 → 代码被删除     │
    └─────────────────────────────────┘
                    │ （通过编译期检查）
                    ▼
    ┌─── 运行时过滤 ──────────────────┐
    │   Level < min_level_?           │
    │   INFO < WARN → return          │
    └─────────────────────────────────┘
                    │ （通过运行时检查）
                    ▼
    ┌─── 格式化 ──────────────────────┐
    │   format ("hello {}", "world")   │
    │   → "hello world"               │
    └─────────────────────────────────┘
                    │
                    ▼
    ┌─── 构建日志行 ──────────────────┐
    │   "[2024-04-05 11:30:45.123]    │
    │    [INFO ] [main. cpp: 15]        │
    │    hello world"                 │
    └─────────────────────────────────┘
                    │
                    ▼
    ┌─── 无锁队列入队 ───────────────┐
    │   tryPush (LogEntry{...})        │
    │   CAS 自旋直到成功              │
    └─────────────────────────────────┘
                    │
        ← 主线程到此返回（非阻塞）→
                    │
                    ▼ （后台线程异步处理）
    ┌─── 批量取出 ────────────────────┐
    │   while (tryPop) batch. push_back │
    └─────────────────────────────────┘
                    │
                    ▼
    ┌─── 写入 ────────────────────────┐
    │   文件: log_file_ << content    │
    │   控制台: cout/cerr << content  │
    │   轮转检查: size > max?         │
    └─────────────────────────────────┘
                    │
                    ▼
    ┌─── 批量刷盘 ────────────────────┐
    │   log_file_. flush ()             │
    │   （一批消息只 flush 一次）      │
    └─────────────────────────────────┘
```
